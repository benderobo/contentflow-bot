Все ошибки и их решения записывать в файл `kill_error.md` (для IN_SITE Studio — `/root/insite-studio/kill_error.md`). При задаче «исправить баг», «написать новую функцию» или «исправить существующую» — сначала прочитать этот файл.

**Why:** пользователь устал от повторяющихся однотипных багов; накопленный журнал ускоряет диагностику и предотвращает регрессии. Пользователь явно указал: "системный промт для тебя чтоб ты проверял себя и записывал баги и решения в файл".

**How to apply:**
1. В начале каждой сессии по IN_SITE Studio — Read `/root/insite-studio/kill_error.md`
2. Перед правкой любого бага или функции — прочитать kill_error.md если ещё не читал
3. После устранения ошибки — дописать запись: дата / Симптом / Причина / Решение / Профилактика
4. Системный промт `/home/insiteagent/insiteagent.md` — это роль для меня при работе с IN_SITE, И системный промт для n8n-агентов (передавать в webhook как `system_prompt`)
5. После правки inline-JS в HTML — всегда проверять синтаксис: `python3 -c "import re,subprocess; ...node -e 'new Function(script)'..."`
