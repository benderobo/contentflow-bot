Сервер `194.87.18.116` (VPN-gateway из [[upgrade-vpn]]-задач: `awg-bot`, `x-ui`, xray на `8444/8445`, Reality на `443`) — это **VPS у хостера JustHost.asia**. Управление через Proxmox-панель `panel.justhost.asia`: **VM `1086004`** (`r1086004.u294817.tscom.kvm.ubuntu-22.04-amd64-r1`) на ноде **`cn301`**, PVE 8.4.19. net0: `virtio`, MAC `FE:25:66:70:fb:3b`, bridge `vmbr0`, rate 25 МБ/с. Внутренний hostname VM — `r1086004`.

Не путать с хостом `b` (`167.17.180.42`, hostname `r1116005`) — это другая машина, с которой шла диагностика.

**Случай 2026-06-02: сервер полностью без сети.** Симптомы и проверенный путь диагностики:
- IP не пингуется ни с одной внешней точки (check-host.net, 5 стран → все TIMEOUT).
- Внутри VM всё корректно: `eth0` UP, `194.87.18.116/24`, `default via 194.87.18.1 dev eth0` — но `ping 194.87.18.1` даёт `Destination Host Unreachable` от своего же IP, а `ip neigh` показывает `194.87.18.1 FAILED`. Это **отказ ARP до шлюза = разрыв на L2**, а не firewall/маршрут/DNS.
- Шлюз недоступен по ARP **и с ноды cn301 тоже** → проблема не в конкретной VM.
- Биллинг JustHost показывал услугу **активной** (без долгов/abuse/suspend).

**Вывод:** при таком наборе (конфиг VM верный, ARP до шлюза FAILED и с VM, и с ноды, IP мёртв глобально, услуга активна) — причина на стороне JustHost: чаще всего **авто-null-route из-за DDoS** на VPN/xray-IP (снимается сам за часы) либо сетевая авария ноды. Чинить в консоли нечего — решается **тикетом в JustHost** с просьбой проверить null-route на IP и аплинк ноды `cn301`. Перед тикетом можно один раз попробовать полный Stop→Start VM.
