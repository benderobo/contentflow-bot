При добавлении или изменении любой функции обязательно:

1. Проследить **весь цикл** задействованных процессов от начала до конца (например: клик → JS-обработчик → обновление состояния → рендер → DOM-обновление → видимый результат)
2. Проверить **визуализацию** — если результат изменения должен что-то показывать на экране, убедиться что именно тот элемент, который **видит пользователь**, получает обновление (а не только скрытый/вспомогательный элемент)
3. Не считать задачу выполненной пока не пройден весь цикл и не подтверждена видимость изменения

**Why:** В сессии insite-studio палитра цветов обновляла `previewCanvas` (скрытая панель на десктопе), но не обновляла `formTplPreview` (видимый элемент). Также переменная `s` не была определена в `selectTemplate()` после рефакторинга — логика "работала" но визуальный результат не появлялся.

**How to apply:** Перед завершением любого изменения — пройти по цепочке: где начинается процесс → что меняется в данных → какой DOM-элемент обновляется → виден ли этот элемент пользователю в текущем layout. Проверить весь путь, а не только изменённый узел.
